პარამეტრები, რომელიც კონფიგურაციას უწევს აპლიკაციას, როგორც განვიხილეთ.

URL– ები, რომლებიც არის ის ნიმუშები, რომელსაც მომხმარებელი მიჰყვება ვებ - პროგრამის კონკრეტულ ნაწილებზე წვდომის მისაღწევად.

ფორმები, რომლებიც განსაზღვრავენ, თუ როგორ ხდება ინფორმაცია, რომელიც სერვერზე იგზავნება და მოცემულია მონაცემთა ბაზაში, ასევე მომხმარებლისთვის. ეს არის სერვერის მხარეზე ინფორმაციის დამუშავების საფუძველი და შეუძლია მიიღოს ნებისმიერი ტიპის ინფორმაცია კომპიუტერის მაღაზიებში, განსაკუთრებით ტექსტურ სტრიქონებზე, ნომრებზე და ჭეშმარიტ/ცრუ ბულეტებზე (ჩვეულებრივ, ყუთები).

შაბლონები, რომლებიც წარმოადგენს HTML კოდს და შაბლონის ენას და ხიბლავს უფსკრული პითონსა და HTML- ს შორის, რაც ნიშნავს, რომ პითონის ინფორმაცია შეიძლება მოემსახუროს როგორც HTML კოდს, რომელსაც ყველას შეუძლია წვდომა და შეძლოს ვებგვერდის შეზღუდული წვდომის უზრუნველყოფა, ხოლო პითონის კოდი ხელმისაწვდომი გახდება დისტანციური მოწყობილობისთვის, რომელსაც არ სჭირდება სერვერის მახლობლად.

სტატიკური ფაილები, რომლებიც, როგორც წესი, JavaScript და მისი ბიბლიოთეკები, რომელსაც სერვერი ემსახურება და უკავშირდება შაბლონს.

მედია ფაილები, რომელსაც სერვერი ემსახურება ან ექსტერნალურად მასპინძლობს, ან უბრალოდ სერვერზე დაწერილი, სანამ დამუშავდება და განთავსდება სხვა სერვერზე (ბუკეტი) ჰოსტინგისთვის.

Middleware, რომელიც არის კოდის ნაწილები, რომლებიც მუშაობს იმავე დროს, როგორც ყველა ხედვა და განიხილება "შედის" თვალსაზრისით.

კონტექსტური პროცესორები, რომლებიც ამუშავებენ თითოეული ხედვის კონტექსტს და გამოიყენება დამატებითი კონტექსტის დასამატებლად.

ტესტები, რომლებიც დაადასტურებენ, რომ მომხმარებელი ან მოთხოვნა გადის გარკვეულ მოთხოვნებს, სანამ ხედვა მოხდება.

მომხმარებლები, რომლებიც კარნახობენ, თუ როგორ გაუმკლავდებიან ვებ - გვერდები და რეაგირებენ კომუნიკაციაზე.

ადმინისტრატორი, რომელიც გამოიყენება მოდელების რეგისტრაციისთვის, რათა მათი მანიპულირება დეტალურად მოხდეს Django Admin გვერდზე, სადაც მონაცემთა ბაზის ადმინისტრირება შესაძლებელია გრაფიკული ინტერფეისით.

ნიახური, რომელიც განსაზღვრავს ასინქრონულ ამოცანებს, Django კოდის ნაწილებს შეუძლიათ დაიწყონ გაშვება, სანამ დაუყოვნებლივ მიიღებთ შემდეგ დავალებას ან კოდის ხაზს.

Django- ს შეიძლება ჰქონდეს მრავალი სხვა კომპონენტი, რომელზეც დეტალურად განვიხილავთ აქ. უამრავი გზა არსებობს, რომ Django უფრო ფუნქციონალური გახადოთ, დაამატოთ ვებ - გვერდები, რომლებიც სწრაფი, გამარტივებული საკომუნიკაციო არხებია, ნიახური, რომელიც ასრულებს ასინქრონულ ამოცანებს და პროგრამული უზრუნველყოფის სხვა ნაწილებს, განსაკუთრებით დანგოს გაფართოებისთვის, განსაკუთრებით ხედვის ფუნქციებში, სადაც კოდების უმეტესობა შესრულებულია. ნახვა ფუნქციები არის მნიშვნელოვანი, რადგან ისინი ჩვეულებრივ აცხადებენ კოდის ყველა ნაწილს, რომელიც სპეციფიკურია სპეციფიკური URL ნიმუშისთვის, ან სერვერის მონაკვეთზე.

პირველ რიგში, მოდით განვიხილოთ View ფუნქციები. ხედვის ფუნქციები იწყება იმპორტის აღნიშვნის კოდით, რომელიც გამოყენებული იქნება ხედვაში, და განისაზღვრება რეგულარული ფუნქციის განმარტებების ან კლასების გამოყენებით. უმარტივესი შეხედულებები განისაზღვრება ფუნქციის განმარტებით DEF და დააბრუნებს Httpresponse ძირითადი შაბლონით. დავიწყოთ ძირითადი შეხედულებისამებრ, ტექსტის "გამარჯობა სამყარო" დასაბრუნებლად. დაიმახსოვრე, რომ ყოველ ჯერზე, როდესაც თქვენ დაამატებთ კოდს DEF– ის მსგავსი განცხადების შემდეგ, თუ, მიუხედავად იმისა, რომ და ა.შ. ჩვენ შევხვდებით იმას, რაც მალე თითოეულ მათგანს ნიშნავს.

ჩვენი საიტის დირექტორია, შეცვალეთ Feed/Views.py ფაილი NANO– ს გამოყენებით და დაამატეთ შემდეგი ხაზები ფაილის ბოლოს.

from django.http import HttpResponse

def hello(request):
    return HttpResponse('hello world')

Django- ს Httpresponse პასუხობს ტექსტური სტრიქონით, რომელიც აღინიშნება გახსნისა და დახურვით. ყოველ ჯერზე, როდესაც ინფორმაციას გადასცემთ ფუნქციას ან კლასს, როგორიცაა მოთხოვნა ან სტრიქონი, თქვენ უნდა გამოიყენოთ ფრჩხილები (გახსნა და დახურვა).

ეს არ არის ყველაფერი, რაც ჯერ კიდევ გვჭირდება ჩვენი შეხედულების სანახავად. რა თქმა უნდა, ჩვენ არ ვუთხარით სერვერს, სადაც ხედია ზუსტად, ჩვენ მაინც უნდა განვსაზღვროთ ის გზა, რომლითაც ხედი უნდა წარმოადგენდეს. დავიწყოთ ძირითადი გზის განსაზღვრით App/urls.py- ში და მოგვიანებით შევხვდებით ბილიკების ჯგუფებში.

App/urls.py- ში, დაამატეთ ხაზი იმპორტის განცხადებების შემდეგ, რაც ჩვენ მხოლოდ ჩვენ შევქმენით ხედი.

from feed import views as feed_views

ახლა, მოდით განვსაზღვროთ ხედვის ნიმუში. ნახვის ნიმუშებს აქვთ სამი კომპონენტი, ბილიკის კომპონენტი, რომელიც ეუბნება სერვერს, სადაც ხედი არსებობს სერვერში (URL ბილიკი, რომელიც მომხმარებელმა აკრიტიკოს ნავიგაციის ზოლში, რომ შევიდეს ვებგვერდზე), ხედვის კომპონენტი, სადაც ხედი არის მითითებული, და მეგობრული სახელია ხედვისთვის, ასე რომ ადვილია მისი შაბლონის შაბლონის მოპოვება, განსაკუთრებით ასე რომ, ეს შეიძლება შეიცვალოს სივრცეზე, თუ განაახლეთ სივრცე. აზრი აქვს ამგვარად გააკეთოთ საქმეები და იყოს მოქნილი, რადგან თქვენი კოდების ბაზა იქნება მუდმივად ცვალებადი გარემო, რომელსაც სჭირდება მოქნილობა და იმპროვიზაცია, რათა იყოს ღირებული და მარტივი მუშაობა. აი, როგორ გამოიყურება თქვენი ხედი, შეგიძლიათ დაამატოთ ეს urlpatterns = [App/urls.py- ის განყოფილება. ხედვის ნიმუში განისაზღვრება ზემოთ აღწერილი სამი კომპონენტით და ფუნქცია, რომელსაც ეწოდება ბილიკი. თქვენი URL ნიმუშები არის სია, ასე რომ დარწმუნდით, რომ ყოველთვის დაასრულეთ მათში თითოეული ელემენტი მძიმით, რადგან ეს ჰყოფს თითოეულ მათგანს. თითოეული ელემენტი ასევე უნდა წავიდეს ახალ ხაზზე, კიდევ ერთხელ, მის წინ ოთხი სივრცე, ისევე, როგორც აპლიკაცია პარამეტრებში. ჩვენ განვსაზღვრავთ ხედვის პირველ კომპონენტს ცარიელი სიმებიანი ფუნქციით, რათა შევქმნათ ხედი, რომელიც გადის ვებ სერვერის ძირეულ დირექტორია. თქვენი urls.py ახლა ასე უნდა გამოიყურებოდეს:

from feed import views as feed_views

urlpatterns = [
    path('', feed_views.hello, name='hello'),
]

ეს არის საფუძველი Django- ს ვებსაიტის შექმნისთვის, რომელიც მთლიანად სტატიკურია. იმისათვის, რომ შევქმნათ უფრო დინამიური ვებსაიტი, სადაც შეგვიძლია დავიწყოთ ინფორმაციის ქეშირების დასაფენად, მაგალითად, სურათები, ვიდეო, აუდიო და სხვა, ჩვენ უნდა გამოვიყენოთ მოდელები, რომელთა შესწავლა შემდეგ. ახლა, მოდით შეამოწმოთ ჩვენი კოდი და გავუშვათ სერვერი. შეცდომების შესამოწმებლად, გაუშვით:

python manage.py check

def send_html_email(user, mail_subject, html_message):
    to_email = user.email
    username = user.username
    if to_email == '':
        return None
    unsub_link = settings.BASE_URL + user.profile.create_unsubscribe_link()
    html_message = html_message + "<p><a href=\"" + unsub_link +  "\" + title=\"Unsubscribe from " + settings.SITE_NAME + " emails\">Unsubscribe</a></p></body></html>"
    msg = EmailMultiAlternatives(mail_subject, strip_tags(html_message), settings.DEFAULT_FROM_EMAIL, [to_email], headers={'List-Unsubscribe' : '<' + unsub_link + '>'},)
    msg.attach_alternative(html_message, "text/html")
    profile = user.profile
    try:
        msg.send(fail_silently=False)
        if not profile.email_valid:
            profile.email_valid=True
            profile.save()
    except:
        profile.email_valid=False
        profile.save()
